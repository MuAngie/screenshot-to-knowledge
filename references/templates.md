# Markdown 模板

除非用户提供自己的规范，否则使用以下结构。Raw Note 的 Frontmatter 不写 `type`、`title`、`source_type`、`source_platform`；主题笔记可保留 `type: knowledge_note`。

## Raw Note

```md
---
created: YYYY-MM-DD
status: 待归档
confidence: medium
category_suggestion:
  - 00_Inbox_待整理
tags:
  - 截图
  - 待整理
source_file: 原始截图路径
---

# 截图 001 原始记录

## 1. 主要内容整理

[基于完整 OCR 和画面上下文整理可确认信息；保留来源内容类型和结构]

## 2. 可提取信息

- 关键词：关键词1、关键词2（最多 4 个） ^keywords
- 关键句：[一句具体核心信息] ^core-summary
- 相关信息：[按需记录对象、平台、行业、方法或案例]

## 3. 原始文字识别

> [保守清理后的完整 OCR；模糊或缺失处明确标注]

## 4. 原图

![[_Source_Images/YYYY-MM/原图文件名.PNG]]

## 5. 不确定信息

- [说明模糊、裁切、遮挡或分辨率不足的位置及其影响；无则写未发现]

## 6. Phase 2 评估预留

- 信息类型：
- 入库判断与理由：
- 建议分类与标签：
- 适合用途：
```

## 主要内容整理规则

- 不重复粘贴 OCR；基于完整 OCR 和画面上下文去除界面噪音与重复内容，重组为可直接阅读的正文。
- 保留可见事实、原意、内容类型、编号、步骤、列表和表格，并纳入必要的界面、图表或图示信息；不要过度压缩。
- 按内容组织：方法保留目标与步骤，报告保留事实字段，资源保留名称、用途和入口；低置信内容只写可确认部分。
- 不加入整理者推论；疑点写入“不确定信息”，推论只写在主题笔记的“我的理解”。

## OCR、关键词与关键句规则

- OCR 只清理明显误识别、重复和多余空格，不改写原文；保留英文、URL、代码、路径和数字单位中的必要空格。
- 从可确认内容中提取 1–4 个关键词，优先选择便于未来检索的具体主题、专有名词、对象、方法、工具或平台，按具体到一般排序。
- 不使用 `截图`、`内容`、`信息` 等空泛词，不堆叠同义词，不采用低置信或推断出的词；产品名和专有名词保留官方写法。
- 关键词行末添加 `^keywords`；完整整理后生成一句不重复正文、不使用套话的 `关键句`，行末添加 `^core-summary`。

## Category Board Page

用户未要求二级主题笔记时，每个一级分类只建一个板块页：

```md
# 分类名称

- 分类：01_选题与内容素材
- 截图数量：N

## Raw Notes

- [[screenshot_001_raw]]：
  ![[screenshot_001_raw#^keywords]]
  ![[screenshot_001_raw#^core-summary]]
```

只嵌入 Raw Note 的 `^keywords` 和 `^core-summary`，不复制预览文字。

## Global Index

总索引只链接分类板块页，不逐条列出 Raw Note：

```md
# 截图整理总索引

- 源目录：
- 输出目录：
- 处理日期：
- 截图总数：
- 文字信息截图：
- 非文字或低文字截图：

## 分类入口

- [[01_选题与内容素材]]：N 张
```

## Topic Knowledge Note

```md
---
type: knowledge_note
created: YYYY-MM-DD
status: 可复用
category:
  - 分类名称
tags:
  - 标签1
  - 标签2
related:
  - "[[相关主题1]]"
source_notes:
  - "[[screenshot_001_raw]]"
---

# 主题标题

## 1. 主题说明

[用 2-4 句话说明核心内容]

## 2. 来源与核心观点

- [[screenshot_001_raw]]
- 观点 1：
- 观点 2：

## 3. 结构化整理

[按内容类型选择字段，参见下表]

## 4. 可复用价值与我的理解

- 可复用价值：
- 我的理解：[明确区分整理者理解与截图原文]

## 5. 行动与关联

- 可行动方向：
- 上级分类：[[分类名称]]
- 强相关主题：[[相关主题1]]
- 延伸主题：[[延伸主题1]]
```

结构化字段按需选用：方法写背景、目标、步骤和注意点；案例写对象、做法、结果和借鉴点；设计写视觉、交互、规则和场景；产品写用户、痛点、方案和机会；学习写概念、解释、例子和易错点。

核心观点必须可追溯到 `source_notes`；整理者推论写在“我的理解”。
