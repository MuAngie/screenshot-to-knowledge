# 分类、归档与命名规则

## 分类表

按未来用途选择一个主分类。Raw Note 仅在分类不明时留在 `00_Inbox_待整理`；分类明确后移入对应目录并更新状态。

| 目录 | 未来用途 |
| --- | --- |
| `00_Inbox_待整理` | 暂存价值或去向不明的 Raw Note |
| `01_选题与内容素材` | 选题、标题、文案、脚本、提示词、文学文艺与展览素材 |
| `02_读书学习` | 书籍、课程、备考、概念与学习材料本身 |
| `05_AI产品经理` | AI 产品机制、岗位、面试、应用策略与产品研究 |
| `06_商业案例` | 商业模式、增长、品牌、营销与公司案例 |
| `07_方法论` | 框架、流程、SOP、复盘、沟通与学习方法 |
| `09_可用工具和网页` | 工具、网站、在线服务、项目、资源目录与链接 |
| `10_生活内容` | 日常、健康、家庭、消费与个人事务 |
| `11_旅行` | 行程、目的地、路线、住宿、餐饮与交通 |
| `12_待判断` | 信息残缺、类别或价值无法确定 |

## 分类决策

1. 先看未来用途，不按平台样式或单个关键词分类。
2. 医疗、身份等敏感记录归 `10_生活内容`，通常标记 `入库但需用户判断`。
3. OCR 主要为乱码、碎片或无法判断时归 `12_待判断`，添加 `OCR低置信度`；不要让孤立的 `ai` 等片段触发 AI 分类。
4. 文学、祝福、情绪表达、艺术与展览素材归 `01_选题与内容素材`。
5. 学习材料本身归 `02_读书学习`；如何学习、阅读或使用 AI 的流程归 `07_方法论`。
6. 城市名本身不代表旅行；出现路线、住宿、景点、餐饮、交通或行程规划语境时才归 `11_旅行`。

- `05_AI产品经理`：AI 产品机制、设计、岗位、面试、应用策略及与权限、体验、数据、定价、风险有关的产品决策。普通 AI 工具、GitHub 项目或零散提示词不归这里。
- `07_方法论` 与 `09_可用工具和网页`：重点是“如何做”归 `07`，重点是“用什么”归 `09`。
- `公司` 不自动归商业案例，`购物` 不自动归生活，城市名不自动归旅行，孤立 OCR 片段不自动归 AI。

## 字段与入库判断

| 项目 | 取值或规则 |
| --- | --- |
| 信息类型 | 观点 / 案例 / 数据 / 方法 / 灵感 / 问题 / 工具资源 / 网页资源 / 行业知识 / 内容素材 / 生活信息 / 旅行信息 / 待判断 |
| 可复用价值 | 高 / 中 / 低 / 待判断 |
| 适合用途 | 写作 / 面试准备 / 竞品分析 / 个人灵感 / 学习复盘 / 项目资料 / 工具收藏 / 生活参考 / 旅行规划 |
| 入库判断：入库内容 | 可读且价值明确，归入最合适的一级分类 |
| 入库判断：待判断内容 | 信息或上下文不足，归 `12_待判断` |
| 入库判断：入库但需用户判断 | 有价值但涉及敏感信息、专业判断或多个合理分类；归最合适分类并用状态或标签提醒，不另建文件夹 |

不强制为每条 Raw Note 创建主题笔记。

## 标签与链接

使用简短中文标签：Raw Note 通常 2–5 个，主题笔记通常 3–8 个。代表性标签包括 `#AI产品经理`、`#内容素材`、`#读书学习`、`#方法论`、`#旅行`、`#健康信息`、`#隐私待确认`、`#OCR低置信度`。

- 同义标签只保留一个稳定名称，避免同时使用 `#AI`、`#人工智能`、`#智能AI` 等近义词。
- 只建立有意义的链接：上级分类 1–3 个、强相关主题 3–5 个、延伸主题 0–3 个。
- 除非用户将其作为索引，否则避免 `[[知识]]`、`[[内容]]`、`[[信息]]` 等空泛链接。

## 命名

Raw Note：

```md
screenshot_001_raw.md
YYYY-MM-DD_主题_raw.md
```

主题笔记：

```md
AI产品经理面试题回答框架.md
东京三日旅行路线.md
```

## 目录结构

分类表中的目录位于默认输出根目录下；另建原图目录：

```md
/Obsidian_Knowledge_Output
  /<分类表中的目录>
  /_Source_Images/YYYY-MM
```
