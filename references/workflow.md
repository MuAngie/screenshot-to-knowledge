# 截图入库工作流

这个文件是工作流路由文件。处理真实截图批次时，先读本文件，再根据当前阶段加载对应的 phase 文件，避免一次性加载所有详细说明。

本工作流的目标不是维护完整知识库，而是把截图摄入为可追溯的 Obsidian 知识层。

## 核心分层

- 原始来源：原始截图和 OCR 文本。不要篡改、补写或美化。
- Raw Note：每张截图对应的一篇低加工 Markdown 原始记录。
- 主题笔记：由一篇或多篇 Raw Note 综合而来的可复用知识页。

## Phase 1：接收与原始记录

读取 `phase-1-intake-raw-capture.md`。

本阶段用于：

- 统计截图数量、确认输入可访问情况，并选择输出方式。
- 区分文字信息截图与非文字内容截图。
- 将非文字内容截图移动到 `_NonText_Images_待整理` 文件夹，记录原始路径和移动后路径，并告知用户。
- 逐张阅读文字信息截图。
- 保留可见文字和画面上下文。
- 为每张截图生成一篇 Raw Note。
- 标注识别层不确定信息。

主要输出：

- 本批处理策略。
- Raw Notes。
- 非文字内容截图移动清单。
- Raw Note 内的识别层不确定信息。

## Phase 2：评估与知识笔记

读取 `phase-2-evaluation-knowledge-notes.md`。

本阶段用于：

- 判断信息类型、可复用价值、适合用途、分类和标签。
- 确认用户偏好，或使用默认配置。
- 判断 Raw Note 是入库内容、待判断内容，还是入库但需用户判断。
- 将已有明确分类的 Raw Note 移入对应一级分类文件夹，并更新归档状态。
- 为每个一级分类生成分类板块页；板块页使用 Raw Note `关键句` 的块嵌入作为预览，不复制另一份摘要。
- 仅在用户要求或主题稳定时生成主题知识笔记。
- 确保每个核心判断都能追溯到 Raw Note。

主要输出：

- 入库判断和处理理由。
- 已归档 Raw Notes。
- 分类板块页。
- 必要时生成主题知识笔记。
- 分类和标签建议。
- 总索引。

## 路由规则

完整处理一个截图批次时，按顺序执行：Phase 1 -> Phase 2。

如果用户只要求检查截图、不生成知识笔记，执行到 Phase 1 后停止。  
如果用户提供了已有 Raw Notes，只要求分类或知识化，从 Phase 2 开始。  

完成前必须核对：Raw Note 数、原图副本数、OCR JSON 数、分类板块页链接数、各分类文件夹实际 Raw 文件数是否一致；如果不一致，先修正缺失文件、坏链接或总索引统计。
