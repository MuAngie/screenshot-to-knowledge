# Phase 2：评估与知识笔记

Phase 2 负责理解、入库、分类、归档和可选主题聚合。先读完整 Raw Note 和原图，再按 `taxonomy.md` 判断；不要只看文件名、OCR 前几行或关键词。

## 1. 评估并对齐结构

- 按 `taxonomy.md` 为每篇 Raw Note 记录主要主题、用途、一级分类、简洁标签、处理理由和入库判断。
- 用户提供 Obsidian 库时沿用现有命名、分类、标签、文件夹和索引；否则使用默认一级分类。
- 只有选择会实质改变归档、主题拆分、敏感信息处理或双链时才询问；否则按最可能的未来用途继续，不改写 Phase 1 的来源事实。

## 2. 归档与分类板块

- 明确分类后，将 Raw Note 从 `00_Inbox_待整理` 移入对应一级分类，并把 `status` 改为 `已归档`。
- 每个有内容的一级分类生成一张板块页。
- 确认 Raw Note 的关键词和关键句末尾分别有 `^keywords`、`^core-summary`；板块页依次嵌入两者，不复制第二份文字。
- 按 `templates.md` 生成唯一的 `YYYY-MM_截图整理索引.md`：沿用类似 `2026-04_截图整理索引` 的批次结构，按分类逐条链接 Raw Note，并在每条下依次嵌入关键词和关键句。
- 在同一个批次索引中逐张链接非文字图片并写明分流原因，再附上覆盖全部处理图片的复制与分流清单。非文字图片不虚构 Raw Note、关键词或关键句。
- 全库总索引仍保持浅层，只链接批次入口和分类板块页，不逐条列出 Raw Notes。

## 3. 可选主题笔记

- 仅在用户要求或材料形成清晰、稳定、可复用主题时创建；单来源主题必须信息充足。
- 按 `templates.md` 写作：观点、方法、案例和数据链接回 Raw Note，整理者推论写入 `我的理解`，只添加有明确语义关系的双链。

## 4. 交付与校验

- 更新 Raw Note 的 Phase 2 字段、Frontmatter、目录和标签；生成分类板块页、合并后的单一批次索引、浅层总索引、待确认清单和必要的主题笔记。
- 执行主 `SKILL.md` 的完成检查。
- 已处理图片总数、已复制图片数和复制清单数必须一致。
- 文字截图数、Raw Note 数、OCR JSON 数、关键词预览数和关键句预览数必须一致。
- 每个板块的 `截图数量` 等于对应目录的 `*_raw.md` 数；所有笔记、图片和块引用均可解析。
- 非文字图片数与分流原因记录数一致；所有复制后路径存在，源文件保持不变。
- 批次索引中的 Raw Note 链接数、关键词预览数和关键句预览数均等于文字截图数；非文字图片链接数等于非文字图片数；复制清单行数等于处理图片总数。
- 合并索引校验通过后，删除同批次独立的 `YYYY-MM_图片复制与分流清单.md`，最终只保留一个批次 Markdown 入口。
