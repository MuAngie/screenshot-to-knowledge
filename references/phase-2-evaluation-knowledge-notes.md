# Phase 2：评估与知识笔记

本阶段用于在阅读 Phase 1 生成的 Raw Notes 后，直接进入 Obsidian 知识库语境，完成内容理解、信息价值判断、入库归类、已有分类读取、分类板块页、必要的待确认项处理，并在确有需要时生成可追溯的主题笔记。默认不要强行细分二级主题，也不要把每张截图都整理成主题笔记。

## Step 1：内容理解与入库判断

### 目标

理解每篇 Raw Note 的主要主题和内容，并从 Obsidian 知识库使用角度判断它应当作为入库内容保留，还是暂时放入待判断。

### 输入

- Phase 1 生成的 Raw Notes。
- `taxonomy.md` 中的分类规则、标签规则、文件夹规则和双链规则。

### 操作

- 识别每篇 Raw Note 中最主要的 1-2 个主题或内容点，防止遗漏用户真正想保留的信息。
- 内容摘要必须基于完整 Raw Note、原图嵌入和 `主要内容整理` 综合判断，不要只看标题、文件名、OCR 前几行或关键词。
- 摘要应回答“这篇 Raw Note 主要保留了什么信息、未来可能为什么有用”。不要把不同类型内容套入固定商业、产品或方法论模板。
- 判断信息类型、可复用价值、适合用途、初步分类、初步标签和可能的知识库位置。
- 将每篇 Raw Note 分为：
  - 入库内容：内容能看懂、有保存价值，且以后可能用于写作、学习、竞品分析、面试准备、灵感整理、工具收藏、生活参考、旅行规划或项目资料等。
  - 待判断内容：内容看不清、OCR 不完整、上下文严重不足、无法判断主要信息，或暂时看不出保存意义。
- 对入库内容继续判断归档方式：
  - 正常入库：主题、用途和分类比较明确，可以进入后续主题聚合。
  - 入库但需用户判断：内容有保存价值，但涉及敏感信息、专业判断边界，或存在多种归类方式且会影响后续整理方向。此类内容单独放入需要用户判断的文件夹，并在 MOC 中提醒用户后续确认。
- 为入库内容记录一级分类。只有用户明确要求主题笔记，或该批截图已经形成稳定主题时，才记录候选主题笔记名。此时只判断单篇 Raw Note 自身，不生成双链；双链和关联依据在后续聚合后再设计。
- 为每条判断写一句简短理由。

### 输出

- 每篇 Raw Note 的主要主题和内容摘要。
- 每篇 Raw Note 的入库判断：入库内容或待判断内容。
- 入库内容的归档方式：正常入库或入库但需用户判断。
- 初步分类和标签建议。
- 一级分类；如需要主题笔记，再给出候选主题笔记名。
- 需要用户后续判断的内容清单。

### 质量检查

不要把信息弱、上下文不足或看不清的截图强行整理成主题笔记。能看懂且有保存价值的内容应当入库；如果只是归类或处理边界不确定，不要直接判为待判断，而应作为入库但需用户判断处理。

## Step 2：已有分类读取与聚合依据确认

### 目标

在主题聚合前，先确认用户已有知识库中的文件夹、分类名称和可能的主题索引，尽量沿用用户已有结构，而不是另起一套分类。

### 输入

- Step 1 生成的入库判断、初步分类和标签建议。
- 用户提供的 Obsidian 库路径、已有文件夹结构、分类规则、标签规则或 MOC，如果有。
- `taxonomy.md` 中的默认分类规则。

### 操作

- 如果用户提供了已有知识库路径或文件管理结构，先读取相关文件夹、分类名称、MOC 或索引文件。
- 将已有分类与 Step 1 的初步分类进行对齐，判断哪些内容可以归入用户已有分类。
- 如果已有分类足够明确，优先基于用户已有分类做主题聚合。
- 如果已有分类不存在、无法访问，或与本批内容明显不匹配，则使用 `taxonomy.md` 的默认分类和模型对内容的理解做聚合。
- 如果某条内容可能归入多个已有分类，且会影响主题聚合方向，标记为需要用户确认。

### 输出

- 本批可沿用的已有分类、文件夹或 MOC。
- 分类对齐结果。
- 无法确定的分类问题。
- 本批主题聚合采用的依据：用户已有分类、默认分类，或两者结合。

### 异常处理

如果用户没有提供知识库路径或已有分类，不要阻塞流程。使用默认一级分类生成分类板块页，并在 MOC 中标注本批未读取到用户已有分类。

## Step 3：分类板块页与可选主题聚合

### 目标

先把 Raw Notes 按一级分类整理为分类板块页。只有用户要求或主题非常稳定时，再把适合进一步知识化的内容整理成可复用、可追溯、可双链的 Obsidian 主题知识页。

### 输入

- 正常入库且适合主题聚合的 Raw Notes。
- Step 2 确认的已有分类、文件夹、MOC 或默认聚合依据。

### 操作

- 优先根据用户已有分类和文件夹结构分组；没有可用已有分类时，使用默认一级分类。
- Raw Note 一旦已经有明确一级分类，就从 `00_Inbox_待整理` 移动到对应一级分类文件夹，并将 frontmatter 中的 `status` 从 `待归档` 改为 `已归档`。只有无法判断分类或需要用户确认归属的内容才继续留在 Inbox 或进入 `12_待判断`。
- 每个一级分类生成一个板块页，列出该分类下的 Raw Note 链接和核心信息预览。
- 分类板块页中的 Raw Note 预览不要复制粘贴一份独立文本。先在 Raw Note 的 `关键句` 行末添加稳定块标识，例如 `^core-summary`；再在分类板块页中使用 `![[screenshot_xxx_raw#^core-summary]]` 嵌入。这样后续修改 Raw Note 的关键句时，分类板块页会同步显示最新内容。
- Raw Note 的 `关键句` 是分类板块页预览的唯一来源。不要在分类板块页里手写另一份摘要；如果用户需要修改预览内容，应改 Raw Note 的 `关键句`。
- `关键句` 不要保留“这张截图主要包含……核心内容是……”这类通用前缀。最终归档时只保留具体核心内容。
- 分类板块页中的核心信息使用每篇 Raw Note 的一句话关键句或内容摘要压缩版，不复制长段 `主要内容整理`。
- 总索引只保留基础信息和分类入口，不要列出每个 Raw Note 的长表格。
- 用户没有想好如何细分时，到分类板块页为止，不要创建二级主题聚合页。
- 为可复用概念、方法、案例、产品参考、设计参考、内容选题或学习材料创建主题笔记。
- 确保主题笔记中的每个核心观点、案例、方法或数据，都能链接回至少一篇 Raw Note。
- 在主题聚合时同步设计 Obsidian 关系：
  - 来源 Raw Notes。
  - 上级分类。
  - 强相关主题。
  - 延伸主题。
  - 不确定或需要用户确认的候选关联。
- 为每条候选双链记录关联依据。双链只记录有明确语义关系的对象，不为增加密度而创建链接。
- 将个人理解放在 `我的理解` 或类似明确标注的小节中。

### 输出

- 分类板块页。
- 如需要，一篇或多篇主题知识笔记草稿。
- 每篇主题笔记对应的来源 Raw Notes。
- 每篇主题笔记的候选分类、标签、文件夹路径和双链。
- 需要用户确认的候选关联。

### 异常处理

如果只有一篇 Raw Note 适合主题聚合，但信息足够强，可以创建单来源主题笔记。如果主题较弱，则只作为入库 Raw Note 保留，不强行生成主题笔记。

### 质量检查

- 每个分类板块页中显示的 `截图数量` 必须等于该分类文件夹中的 `*_raw.md` 文件数。
- 所有分类板块页中的 Raw Note 链接都必须能在对应分类文件夹或输出目录中找到实际文件。
- 已归档 Raw Note 不应继续留在 `00_Inbox_待整理`；如果 Inbox 为空，可以删除空文件夹。
- Raw Note 总数、原图副本数、OCR JSON 数应与原始文字截图数量一致；若不一致，先定位缺失项并补齐或在总索引中明确说明。
- 分类板块页中的预览嵌入数量应等于 Raw Note 总数。

## Step 4：待确认项处理

### 目标

只处理 Step 2 和 Step 3 后仍无法自动决定、且会影响归档、主题拆分、双链或处理边界的问题。本步骤可跳过；如果没有关键不确定项，直接进入 Step 5。

### 输入

- 用户已有的知识库规则，如果有。
- Step 1 生成的入库判断、初步分类和标签建议。
- Step 2 读取到的已有分类、文件夹、MOC 或默认聚合依据。
- Step 3 生成的主题聚合结果、候选双链和需要确认的候选关联。

### 操作

- 只有在以下情况出现时才向用户确认：
  - 没有读取到用户已有分类，但最终归档选择会明显影响后续使用。
  - 某些内容可归入多个分类，且会影响主题笔记拆分。
  - 某些候选双链或主题关联不确定。
  - 内容涉及敏感信息、隐私内容或专业判断边界。
  - 用户明确要求使用自己的命名、标签、文件夹或双链规则。
  - 默认规则和用户已有结构冲突。
- 如果用户跳过确认，使用 Step 2 的已有分类或 `taxonomy.md` 默认规则继续。
- 不回头改写 Phase 1 的原始事实记录；偏好只影响最终归档、格式化、标签、双链和交付。
- 如果用户确认结果与初步分类冲突，优先使用用户确认结果，并在 MOC 中标注被调整的归档选择。

### 输出

- 已确认的问题和处理决定。
- 未确认但继续使用默认规则处理的问题。
- 修正后的分类、标签、命名、文件夹方向和双链策略。

### 异常处理

如果没有关键不确定项，不要为了确认而打断流程。直接使用 Step 2 的聚合依据和 Step 3 的候选关联进入 Step 5。

## Step 5：Obsidian 格式化

### 目标

将前面已经形成的 Obsidian-aware 知识结构整理为可以直接放进 Obsidian 使用的 Markdown 文件。

### 输入

- Raw Notes。
- 主题笔记。
- 已确认的分类、标签、命名、文件夹和双链规则。
- 主题聚合阶段生成的来源关系和候选双链。

### 操作

- 添加 YAML Frontmatter。
- 添加简洁标签。
- 将已确认的候选双链转为 Obsidian 双链。
- 删除空泛、无依据或未确认的双链。
- 在主题笔记中添加 `source_notes`。
- 建议文件夹路径。

### 输出

- Obsidian-ready Markdown 文件。

### 质量检查

避免生成 `[[知识]]`、`[[信息]]`、`[[想法]]` 这类空泛双链，除非它们是用户明确使用的知识库索引。
